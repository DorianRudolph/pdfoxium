# Pinned PDFium raster expectations

These test-only files are lossless unpackings of explicitly selected committed
PNG expectations from PDFium revision
`f51279699cb59754d1f49aef10eb8e825fe56532`. No expected pixel was captured from
pdfoxium or regenerated by rendering a PDF. Source paths, SHA256 hashes,
dimensions, palette/RGB mode, alpha extrema, packed RGBA hash and complete raw
file hash are recorded in [manifest.json](manifest.json).

PDFium is Copyright 2014 The PDFium Authors and distributed under its BSD
license; the notice and terms are reproduced in [LICENSE](LICENSE). The source
fixtures, PNGs and full upstream licensing are retained under
[upstream/pdfium](../../../../upstream/pdfium). These raw copies do not introduce
a production dependency or change a source fixture's license.

The inventory contains ten `pixel/` expectations for Type3 fonts, image glyphs,
mesh shadings, affine image transforms, ICC recovery and JPX dictionary variants,
plus 27 `embedder_tests/` expectations used by connected font/parser and
image/editing C API tests. The exact Linux AGG/generic source files are selected
in the generator; there is no platform/backend suffix fallback at runtime.

All samples are preserved, including alpha and RGB of fully transparent pixels.
Palette transparency is expanded to straight RGBA without compositing, color
management, resizing or quantization. Most images are opaque, while clipped
images and fill-pattern cells retain genuine transparent pixels. The 37 raw
files occupy **16,629,188 bytes**, including their headers.

Each `.rgba` file has a 12-byte header, `struct.pack('<4sII', b'PDRG', width,
height)`, followed by tightly packed top-down straight RGBA8. The C++ harness
validates this header/size and swaps red/blue for its BGRA representation. PNG
decoding and Pillow are not runtime dependencies of the C++ tests.

Regenerate or verify with developer-only Pillow (verified with Pillow 12.3.0):

```sh
python3 -m pip install Pillow==12.3.0
python3 tests/capi/resources/pixel_goldens/generate.py
python3 tests/capi/resources/pixel_goldens/generate.py --check
```

`--check` performs the same lossless conversion and compares every raw byte and
all manifest fields without writing. Inputs remain in the read-only upstream
checkout. Normal C API tests read the checked-in raw files directly.

The ten pixel PDFs are generated at build time into the target directory using
upstream's existing standard-library-only template expander:

```sh
python3 upstream/pdfium/testing/tools/fixup_pdf_template.py \
  --output-dir <generated-pixel-directory> \
  upstream/pdfium/testing/resources/pixel/type3.in \
  upstream/pdfium/testing/resources/pixel/type3_xobject.in \
  upstream/pdfium/testing/resources/pixel/shade.in \
  upstream/pdfium/testing/resources/pixel/shade-tensor.in \
  upstream/pdfium/testing/resources/pixel/image_transformer_other.in \
  upstream/pdfium/testing/resources/pixel/icc_profile_bad_component.in \
  upstream/pdfium/testing/resources/pixel/icc_profile_bad_value.in \
  upstream/pdfium/testing/resources/pixel/jpxdecode_without_colorspace.in \
  upstream/pdfium/testing/resources/pixel/jpxdecode_with_mismatch_colorspace.in \
  upstream/pdfium/testing/resources/pixel/jpxdecode_smask_in_data_2.in
```

The template expander resolves its original relative JPX includes and computes
stream lengths/xrefs. It must not write generated PDFs into upstream. The C++
compile definition `PDFOXIUM_PINNED_PIXEL_DIR` identifies that generated directory.
